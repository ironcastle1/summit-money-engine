# Analysis model

## Core objective

Merlin ranks information by **assessment value**, not by popularity.

A development receives attention when it combines several of the following:

- high-quality or primary evidence
- freshness
- priority geography
- priority-country relevance
- material event type
- escalation/de-escalation indicators
- corroboration
- market transmission
- critical dependency exposure
- scenario-playbook match
- practical security consequence

## Evidence policy

An official source is authoritative for what that institution announced or did. It is not automatically authoritative for every factual claim contained in a political or military statement.

State-controlled media can be useful for eventling intent and domestic narratives, but it is discounted as independent corroboration.

High-consequence claims such as imminent attacks, battlefield outcomes, chokepoint closures, bank insolvency and nuclear weaponisation receive explicit claim-risk penalties until independently corroborated.

## Adaptive collection

The first collection stage provides broad but targeted coverage across the five priority regions.

After initial scoring, Merlin identifies high-value events that are still under-corroborated. It builds narrow follow-up GDELT queries using the event's priority location, category and distinctive title terms. These follow-up results are passed through the same source-quality and tabloid filters before the final event set is rebuilt.

This means collection effort is concentrated where uncertainty and assessment value are both high.

## Financial interpretation

Merlin does not turn a headline directly into a trade instruction.

It first asks:

1. Is there a known physical, legal, monetary or supply-chain transmission mechanism?
2. Is the relevant asset actually exposed to that mechanism?
3. What would confirm the mechanism is active?
4. What would invalidate it?
5. What is the plausible transmission lag?

The UI therefore shows exposures, potential beneficiaries/pressure points and scenario conditions rather than buy/sell commands.

## Security interpretation

Security actions are verification tasks rather than alarmist instructions. Examples include checking:

- official NOTAMs
- maritime-security advisories
- port conditions
- carrier routing
- embassy ordered-departure notices
- border restrictions
- operator outage statements
- grid/utility notices

The goal is to convert a headline into concrete things the customer can verify.
